# 知识类型标准（对应 K-04 知识库标准规范）

> 本文件定义入库知识的五大类型、必备字段、结构要求与质量红线。所有入库文档须先对照本标准编写或改造，再提交审核。

## 一、知识类型定义

| 类型代码 | 类型名称 | 典型来源 | 主要形态 |
| --- | --- | --- | --- |
| policy | 政策文件 | 学校发文、部门规章 | 章-条结构正式文件 |
| guide | 办事指南 | 部门办事流程、服务说明 | 步骤化流程文档 |
| faq | 常见问题 | 咨询台记录、电话/在线咨询整理 | 一问一答（含变体问法） |
| item | 服务事项 | 一网通办平台事项数据 | 结构化事项信息（条件/材料/流程/时限） |
| org | 组织机构信息 | 学校官网、通讯录 | 单位职能、联系方式、办公地点 |

## 二、必备字段（frontmatter）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| title | ✅ | 文档标题，与正文一级标题一致 |
| dept | ✅ | 归口部门（信息网络中心/财务处/后勤处/国有资产管理处/本科生招生办…） |
| ktype | ✅ | policy / guide / faq / item / org |
| visible_roles | ✅ | 可见角色，逗号分隔：访客/本科生/研究生/教职工/离退休人员/全部 |
| status | ✅ | 草稿 / 已审核（已审核才会入库生效） |
| updated | ✅ | 内容基准日期（YYYY-MM-DD），用于时效性校验 |
| source | ✅ | 文件来源与文号；示例数据须标注"示例数据（待替换为学校真实文件）" |

> xlsx/csv 等表格文件无法携带 frontmatter，dept 与 ktype 由所在目录推断，visible_roles 默认"全部"。

## 三、结构要求

### 政策文件（policy）

- 保留章-条结构：一级标题 = 文件名，二级标题 = 章，条目使用"第X条"编号段落
- 删除公文格式元素（签发人、抄送、印发日期等与问答无关的内容）

### 办事指南（guide）

- 按「适用范围 → 条件/材料 → 步骤 → 时限 → 收费 → 咨询渠道」组织
- 步骤必须有序号；涉及收费、时限、标准的用表格呈现
- 结论前置：最关键结论（去哪办、带什么、多久）放在开头

### 常见问题（faq）

- 一个问题一个二级标题（`## 问：xxx`），答案紧跟其后，末尾附 2-3 条同义问法
- 答案 ≤300 字，结论先行；涉及数字（费用/时限/标准）必须明确
- 批量整理可使用 JSON 或 xlsx 格式（见《FAQ问答对规范》）

### 服务事项（item）

- 字段固定：事项名称 / 受理部门 / 办理条件 / 申请材料 / 办理流程 / 办理时限 / 收费情况 / 办理渠道
- 与一网通办平台事项数据保持同步，事项 ID 唯一

### 组织机构（org）

- 单位名称 / 职能简介 / 办公地点 / 办公电话 / 服务时间 / 官方网站

## 四、质量红线

1. **时效性**：所有含数字的结论（标准、费用、时限）必须可追溯到 source 原文件；政策类知识超过 2 年未复核自动标记"待复核"
2. **口径一致**：同一事实（如某事项办理时限）在多份文档中出现时必须一致；冲突以归口部门最新文件为准
3. **单一主题**：一份文档只写一件事，混合内容必须拆分为多份
4. **脱敏**：不得包含个人隐私信息（学号、身份证、手机号）与非公开内部信息
5. **可独立引用**：每个知识片段脱离上下文仍可理解——这是切片的最小质量单位

## 五、状态流转

```
草稿 →（部门联络员提交）→ 待审核 →（管理员审核）→ 已审核（入库生效）
                                        ↘ 已驳回（退回修改）
```

对应招标条款 M-K-05（知识审核：审核通过的文档才可进行知识问答）。
