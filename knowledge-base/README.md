# 能小智 · 知识库（内容工程框架）

> ⚠️ 当前目录下所有知识文档均为**示例占位数据**，仅用于知识管线验证与检索效果调优。正式实施时必须替换为学校各部门提供的真实文件。

## 一、目录结构

```
knowledge-base/
├── 00-知识标准/            # 知识编写规范与模板（管理文档，不入库）
├── 01-信网中心/            # 一级目录 = 归口部门（对应知识库授权边界 M-K-03）
│   ├── 办事指南/           # 二级目录 = 知识类型（对应 K-04 知识标准）
│   ├── 常见问题/
│   ├── 政策文件/
│   └── 服务事项/
├── 02-财务处/
├── 03-后勤处/
├── 04-国有资产管理处/
├── 05-本科生招生办/
└── 收集清单.md             # 各部门知识收集任务台账
```

规则：

- 以 `00-` 开头的目录和根目录散放的文件**不会**被引擎收录（属于管理文档）
- 新增部门：新建 `编号-部门名` 一级目录，编号顺延（如 `06-教务处`）
- 二级目录按需创建，建议齐备四类：`政策文件 / 办事指南 / 常见问题 / 服务事项`

## 二、分类体系（三个维度）

| 维度 | 载体 | 对应招标条款 |
| --- | --- | --- |
| 部门 | 一级目录 + frontmatter.dept | M-K-03 多部门知识库分类授权 |
| 知识类型 | 二级目录 + frontmatter.ktype | K-04 知识标准规范 |
| 可见角色 | frontmatter.visible_roles | P-B-07 会话智能路由（同一问题按身份返回不同答案） |

## 三、文档规范

每份知识文档以 YAML frontmatter 开头：

```yaml
---
title: 差旅费报销指南
dept: 财务处
ktype: 办事指南            # policy / guide / faq / item / org
visible_roles: 教职工, 研究生   # 访客/本科生/研究生/教职工/离退休人员/全部
status: 已审核             # 草稿状态的文档不入库（模拟审核门槛 M-K-05）
updated: 2026-09-01
source: 陕科大财〔2024〕X 号
---
```

详细规范见 [00-知识标准/知识类型标准.md](00-知识标准/知识类型标准.md) 与 [00-知识标准/FAQ问答对规范.md](00-知识标准/FAQ问答对规范.md)。

## 四、与 kb-engine 的关系

`kb-engine/`（Node.js 原型引擎）扫描本目录并完成：

```
本目录文档 → 解析（md/docx/pdf/xlsx/csv/json）→ 切片（标题层级 · 表格整块 · FAQ整对）
→ 向量化（bge-small-zh-v1.5 本地模型）→ data/store.json
→ 混合检索（向量 + BM25 + RRF 融合，按角色过滤可见切片）
```

常用命令（在 `kb-engine/` 目录下执行）：

```bash
npm run ingest                            # 重建知识库索引
npm run ask -- "差旅住宿费标准是多少" --role 教职工
```
